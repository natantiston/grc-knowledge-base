# 20.16 Security Awareness Terms

This section defines the core terminology associated with **Security Awareness, Security Culture, Cybersecurity Education, Security Training, Human Risk Management, Social Engineering, Phishing, Insider Risk, Security Behavior, and Security Awareness Governance**.

> **Terminology note:** This glossary is designed for the GRC knowledge base and aligns broadly with concepts found in **ISO/IEC 27001, ISO/IEC 27002, NIST Cybersecurity Framework, NIST security-awareness guidance, CIS Controls, and modern Human Risk Management practices**.

---

# Security Awareness Glossary

| Term                                     | Definition                                                                                                                                                                    |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Security Awareness**                   | The understanding employees and relevant personnel have of cybersecurity risks, policies, responsibilities, and expected secure behaviors.                                    |
| **Cybersecurity Awareness**              | Awareness of cyber threats, vulnerabilities, security controls, and behaviors required to protect systems, information, and organizations.                                    |
| **Information Security Awareness**       | Awareness of information-security risks, requirements, policies, and secure information-handling practices.                                                                   |
| **Security Awareness Program**           | Structured organizational program designed to educate personnel, influence behavior, reduce human-related risk, and strengthen security culture.                              |
| **Security Training**                    | Formal education designed to develop the knowledge and skills required to perform security responsibilities effectively.                                                      |

# Knowledge vs. Awareness vs. Behavior

These three concepts should not be treated as the same.

### Knowledge

> **Does the employee know what to do?**

Example:

Employee knows that suspicious emails should be reported.

### Awareness

> **Does the employee recognize why it matters?**

Example:

Employee understands the consequences of clicking a malicious link.

### Behavior

> **Does the employee actually do the right thing?**

Example:

Employee reports the suspicious email instead of clicking it.

Therefore:

**Knowledge**

↓

**Awareness**

↓

**Behavior**

↓

**Reduced Human Risk**

# Security Awareness Maturity Model

A useful five-level model for the GRC knowledge base:

| Level       | Maturity   | Characteristics                                                                            |
| ----------- | ---------- | ------------------------------------------------------------------------------------------ |
| **Level 1** | Ad Hoc     | Minimal training; reactive awareness                                                       |
| **Level 2** | Developing | Basic annual training and policies                                                         |
| **Level 3** | Defined    | Structured program, campaigns, metrics, role-based training                                |
| **Level 4** | Managed    | Risk-based training, behavioral measurement, simulations, targeted interventions           |
| **Level 5** | Optimized  | Continuous behavioral improvement, human-risk analytics, adaptive training, integrated GRC |

---

# Security Awareness Measurement

A mature program should measure more than **training completion**.

### Level 1 — Participation

**Training Completion Rate**

→ Did employees complete the training?

### Level 2 — Knowledge

**Assessment Score**

→ Did employees understand the material?

### Level 3 — Behavior

**Phishing Click Rate**

→ Did employees behave securely?

### Level 4 — Reporting

**Phishing Report Rate**

→ Did employees recognize and report threats?

### Level 5 — Risk

**Human Risk Reduction**

→ Did the program actually reduce organizational risk?

Therefore:

> **Completion ≠ Effectiveness**

A 100% training completion rate does not necessarily mean employees are secure.

# Security Awareness and Insider Risk

Security awareness is an important preventive layer against insider risk.

### Negligent Insider

**Lack of awareness**

→ Mistake

→ Security incident

### Malicious Insider

**Intentional misuse**

→ Policy violation

→ Security incident

### Compromised Insider

**Account compromise**

→ Attacker impersonates employee

→ Security incident

Therefore:

> **Security awareness reduces some forms of insider risk, but it cannot eliminate insider risk.**

Technical and governance controls remain necessary.

# Security Awareness and AI

Modern awareness programs should include **AI security awareness**.

Employees should understand risks such as:

* entering confidential information into public AI tools;
* exposing personal data through prompts;
* uploading proprietary documents;
* relying on inaccurate AI-generated information;
* AI-generated phishing;
* deepfakes;
* voice cloning;
* prompt injection;
* malicious AI-generated code;
* unauthorized "Shadow AI";
* AI-assisted social engineering.

A useful model is:

**AI Tool**

→ **What data are you entering?**

→ **Where does the data go?**

→ **Who can access it?**

→ **Is the tool approved?**

→ **Can the output be trusted?**

→ **Does human review remain necessary?**

# Key GRC Takeaway

The traditional view of security awareness is:

> **"Train employees once a year."**

A mature GRC approach is:

> **Identify Human Risk → Educate → Test → Measure Behavior → Intervene → Monitor → Improve**

The ultimate objective is not simply:

**100% Training Completion**

but:

> **Measurable reduction in human-related cybersecurity risk.**

In a mature organization, **security awareness becomes part of the control environment and security culture**, connecting **people, processes, technology, risk management, compliance, incident management, and continuous improvement**.
